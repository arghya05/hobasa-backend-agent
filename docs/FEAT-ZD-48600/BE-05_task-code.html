overdue_with_risk works in four steps (feat.design B3.2; tool:repo):

  1. It skips an invoice when inv.get("paid") is truthy. aging_buckets uses the same test (D-2026-050).
  2. It computes days = days_past_due(inv["due_date"], as_of), reusing days_past_due unchanged (calendar days,

D-2026-031). It skips the invoice when days <= OVERDUE_AFTER_DAYS, so only invoices more than 30 days past due are kept and an invoice exactly 30 days past due is not listed. It never calls bucket_for. An inline comment says why: bucket_for(30) returns "31-60".

  1. It builds a row with exactly the keys id, vendor, days, amount and risk:
  2. amount is Decimal(inv["amount"]).quantize(TWO_PLACES);
  3. risk is risk_by_vendor.get(inv["vendor"], "unknown");
  4. vendor is read by indexing (inv["vendor"]), so a missing vendor on an overdue unpaid invoice raises

KeyError.

  1. It sorts with rows.sort(key=lambda row: (-row["days"], row["id"])) and returns the list.

as_of is a required argument with no default. The function builds a new list of new row dicts and does not modify its inputs (tool:repo; feat.design NF-10).

overdue_rows_to_json is a single json.dumps call over a list comprehension (tool:repo; feat.design B3.2). Each object has its keys in CT-1 order:

  • id;
  • vendor;
  • days, as int(r["days"]);
  • amount, as str(Decimal(r["amount"]).quantize(TWO_PLACES));
  • risk.

Rows keep their order, and no date field is added. Neither function uses float (tool:repo; record:memory D-2026-044; org.lessons L-011).

Unchanged: BUCKETS, days_past_due, bucket_for and aging_buckets keep the signatures and bodies that task.components section 1 records (tool:repo; task.components; AC-05.9).

Comments and docstrings (tool:repo):

  • The overdue_with_risk docstring states the row keys, the sort order, the 'unknown' default for a vendor missing

from risk_by_vendor, the KeyError for a missing vendor, and that the function is pure.

  • The overdue_rows_to_json docstring states the CT-1 shape, the '[]' result for no rows, that rows keep their

order, and that the amount never passes through float.

  • The comment above OVERDUE_AFTER_DAYS says an invoice is overdue only when strictly more than this many calendar

days past due, so exactly 30 is not listed.

  • The comment above the threshold check in overdue_with_risk explains why bucket_for is not used:

bucket_for(30) is "31-60", but an invoice exactly 30 days past due must not be listed.
